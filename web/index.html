Decoder test harness

Benign fuzz inputs only — truncated, garbage, structurally-invalid Brotli. This lab ships no weaponized OOB-write / RCE payload. A reject (422) = runtime cleanly refused hostile input. A crash (connection reset / refused) = the target process died mid-decode.

The vulnerable sink

Any service that decompresses an untrusted Brotli body hits this. Express apps that accept Content-Encoding: br and inflate the body before parsing are the classic exposure.

app.post('/upload', (req, res) => { const raw = Buffer.concat(chunks); // attacker-controlled bytes const data = zlib.brotliDecompressSync(raw); // <-- OOB write on unpatched Node ... });
Fix = upgrade the runtime (Node 22.23.4+ / 24.22.1+ / 26.12.1+, Bun 1.4.4+). No code change makes the decode safe on a vulnerable runtime; reject br at the edge only as a stopgap.
